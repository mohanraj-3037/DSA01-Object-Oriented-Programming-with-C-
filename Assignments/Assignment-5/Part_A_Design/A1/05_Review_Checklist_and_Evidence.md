# A1 – Review Checklist and Evidence

## Before submission

- [ ] Common data are identified and justified.
- [ ] `total()` is pure virtual.
- [ ] `type()` is pure virtual or its chosen design is justified.
- [ ] `print()` is included and its common/virtual status is explained.
- [ ] `Bill` has a virtual destructor.
- [ ] Four required derived classes are present.
- [ ] Out-patient formula includes consultation and tests.
- [ ] In-patient formula includes room-per-day, procedures and medicines.
- [ ] Day-care calculation uses package price.
- [ ] Emergency calculation includes base and time-based charges.
- [ ] UML marks abstract class, pure virtual operations, overrides and inheritance.
- [ ] Daily-total pseudocode uses an array of base-class pointers.
- [ ] Pseudocode follows the SIMATS algorithmic style.
- [ ] Loop correctness and assumptions are explained.
- [ ] Tagged-structure alternative is described.
- [ ] O(n) time for both approaches is stated.
- [ ] Per-object storage and extension differences are compared.

## Evidence expected by the assignment

The A1 evidence is design evidence:
1. Common interface description.
2. UML hierarchy diagram.
3. Pseudocode for processing mixed bills.
4. Alternative design and complexity comparison.

Part A does not require measured timing for A1. If measurements are added, they should be actual measurements and must not replace the required Big-O reasoning.
