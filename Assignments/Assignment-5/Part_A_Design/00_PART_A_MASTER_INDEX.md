## Five artefacts per task

Each task folder contains:
1. **Task requirements and mark breakdown** – exact assessed expectations.
2. **Complete design answer** – expanded written response.
3. **Task-specific Mermaid `.mmd`** – editable source placed inside the task folder.
4. **Alternative concept and complexity analysis** – required alternative approach, time and space comparison.
5. **Review checklist and evidence notes** – confirms that every requirement is covered.

## Mermaid conversion

Open each `.mmd` file in a text editor, copy its contents, and paste into [Mermaid Live Editor](https://mermaid.live/). Export as SVG or PNG if the report requires rendered diagrams. Keep the `.mmd` source in the submission repository.

## Pseudocode compliance

The algorithms are written using named `ALGORITHM`, `DECLARE`, `SET`, `IF`, `FOR`, `SWITCH`, `RETURN`, `DISPLAY` and `REPORT` constructs. They are deliberately pseudocode, not C++ syntax, because the brief says C++ code will not be accepted in place of Part A pseudocode.

## Academic integrity and evidence

Output predictions are supplied as prediction drafts with explanations. Follow the assignment instruction by recording your prediction before executing the corresponding program. Actual compiler output, sanitizer diagnostics, screenshots and measurements must come from your own run; they should not be invented or substituted with illustrative values.
